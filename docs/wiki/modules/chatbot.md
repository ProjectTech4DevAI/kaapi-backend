# Module: Chatbot

Prompt-driven chatbot over LangGraph and a LangChain chat model (Anthropic), with two agents picked per session by `agent_type`: `onboarding` ("Beneficiary Info Extractor"; the admin's free-text `system_prompt` defines the goal, the fields to collect, and the rules; each turn extracts the fields the user has given so far and then replies) and `rag` (answers questions from the config's knowledge bases, i.e. OpenAI vector stores searched with the project's OpenAI credentials; `system_prompt` is the goal and decides scope). The model and reasoning settings come from a saved Kaapi config (`config_id` + optional `config_version`, latest if omitted); only Anthropic text completion configs are supported. Conversations are server-side sessions whose turns run on Celery and reply via webhook. No deep-dive doc yet.

All paths relative to `backend/app/`.

## Routes
- `api/routes/chatbot/session.py`
  - `POST /chatbot/sessions` (create; validates the config, and for `agent_type=rag` also the knowledge bases + OpenAI credentials via `prepare_rag_search_client` → 422; `chatbot_ref` omitted → new chatbot, ref generated by `services/chatbot/chatbot_ref.py:generate_chatbot_ref`; given → existing chatbot, supersedes the contact's active sessions for it → `{session_id, chatbot_ref}`; 409 on a concurrent create, 503 if no unused ref could be generated)
  - `GET /chatbot/sessions?contact_ref=&chatbot_ref=` (latest session for a contact in the caller's project; `chatbot_ref` optional — omitted means newest across all chatbots → `ChatbotSessionSummary`, incl. `chatbot_ref`, `system_prompt`, `agent_type`, `status`, `completion_status`, `collected_fields`)
  - `POST /chatbot/sessions/{session_id}/message` (stores the user message, enqueues the turn → 202; reply POSTed to `webhook_url`; 409 if the session is inactive)
- All require project scope and the `CHATBOT` feature flag (`require_feature` on the `/chatbot` router → 403 when off). Migration `089` only adds the enum value — no rows are seeded, so the flag is off until a superuser creates it per project via `POST /feature-flags` (`enabled: true`).

## Tables (SQLModel, `models/chatbot.py`)
- `chatbot_session` (`ChatbotSession`) — `name` (display only), `contact_ref` (end user), `chatbot_ref` (stable chatbot id, generated as `LLMResponseWithPrompt-<5 hex>` on the first create and unique per project; caller sends it back to start new sessions for the same chatbot), `config_id` (FK `config`, RESTRICT) / `config_version`, `system_prompt`, `agent_type` (`ChatbotAgentTypeEnum` onboarding/rag, PG enum `chatbotagenttypeenum`, server default `onboarding`; migration `090`), `status` (`ChatbotSessionStatusEnum` active/inactive = session in use), `completion_status` (`ChatbotCompletionStatusEnum` in_progress/complete/abandoned), `collected_fields` (JSON flat `{field_name: value}`), org/project FKs. Composite index `(project_id, chatbot_ref, contact_ref)` for GET-latest and the generated-ref collision check, plus a partial unique index on `(project_id, contact_ref, chatbot_ref) WHERE status = 'active'`. Migration `088`.
- `chatbot_session_message` (`ChatbotSessionMessage`) — ordered transcript rows (`role` user/assistant; the prompt lives on the session).
- Session lifecycle: one active session per contact + chatbot. `active`+`in_progress` → `active`+`complete` as fields are collected. Creating a new session for the same `contact_ref` + `chatbot_ref` (same transaction as the insert) moves the previous active ones to `inactive`+`complete`, or `inactive`+`abandoned` if still in progress. Inactive sessions reject new messages (409); a turn already queued when the session was superseded is skipped by the worker, which posts a failure webhook instead. A partial unique index `uq_chatbot_session_active_contact_chatbot` (`WHERE status = 'active'`) makes a concurrent double-create fail; crud raises `ChatbotSessionConflictError` → 409.
- Request/response shapes: `CreateChatbotSessionRequest/Response`, `ChatbotSessionSummary`, `SendChatbotSessionMessageRequest/Response`.

## Turn flow (onboarding agent, `services/chatbot/agents/onboarding/graph.py`)
1. `extract_fields_node` — skipped until there is a real user turn (opening greeting). Otherwise calls the model with structured output (`FieldExtraction{collected_fields, missing_fields, is_complete}`) over the admin prompt, the previously collected map, and the (summarized) conversation. Uses Anthropic native structured output (`with_structured_output(..., method="json_schema")`) with the config's own thinking/effort, because forced tool use is rejected with thinking on and Opus 5.5 can't disable thinking. Merged in code: `{**prior, **extracted}`; `is_complete` only when nothing is missing.
2. `chatbot_node` — replies using the same summarized view plus a system note listing collected/missing fields, so it asks only for what's missing and wraps up when complete.
3. `run_chatbot_turn(..., collected_fields=prior)` → `ChatbotTurnResult{reply, collected_fields, is_complete, sources=[]}` (`.completion_status` maps to the enum). Anthropic errors from either call, and langchain_anthropic's client-side model-config `ValueError`s ("[KAAPI] Unsupported model configuration"), map to `ChatbotProviderError` via the shared `provider_errors.to_provider_error`, so the session path always sends a failure webhook.

## Turn flow (rag agent, `services/chatbot/agents/rag/graph.py`)
1. `prepare_context_node` — runs `summarize_if_needed` once and replaces the state messages (`RemoveMessage(REMOVE_ALL_MESSAGES)`), so the tool loop is never summarized mid tool_use/tool_result pair.
2. `agent_node` — chat model with `search_knowledge_base` bound (`tool_choice` auto; forced tool use is rejected with thinking). System prompt = `RAG_INSTRUCTION` + `<config_instructions>` (config `params.instructions`, if set) + `<goal>` (session `system_prompt`). After `MAX_TOOL_ROUNDS` (3) tool-calling AIMessages it is re-bound with `tool_choice={"type": "none"}` so it must answer.
3. `tools_condition` → `ToolNode` (`tools`) → back to `agent_node`; END once the model stops calling tools. Only bad tool args (`ToolInvocationError`) are fed back to the model; a search failure (`ChatbotProviderError`) fails the turn.
4. `search_knowledge_base(query)` (`retriever.py`, `content_and_artifact`) — `client.vector_stores.search` on every `knowledge_base_ids` entry, merged, sorted by score, top `max_num_results` (default 5, capped at 50); content is `<source file="...">text</source>` passages, artifact the `KnowledgeBasePassage` list. OpenAI errors → `ChatbotProviderError` (`[OPENAI] Knowledge base search failed ...`; timeouts/connection `[KAAPI]`).
5. `run_rag_turn(..., openai_client)` → `ChatbotTurnResult{reply, collected_fields (unchanged), is_complete=False, sources}`; `sources` are the retrieved files deduped by `file_id`.

## Services / CRUD
- `services/chatbot/agents/onboarding/graph.py` — `run_chatbot_turn` (public entry point), `build_onboarding_graph`, the extraction/reply nodes
- `services/chatbot/agents/onboarding/prompts.py` — extraction instruction/templates, progress-note templates, `EXTRACTION_METHOD`
- `services/chatbot/agents/onboarding/types.py` — `OnboardingState`, `FieldExtraction`
- `services/chatbot/agents/rag/graph.py` — `run_rag_turn` (public entry point), `build_rag_graph`, `build_rag_system_prompt`, `MAX_TOOL_ROUNDS`
- `services/chatbot/agents/rag/retriever.py` — `get_knowledge_base_client` (project OpenAI credentials → client; missing → `ChatbotInputError`), `search_knowledge_bases`, `format_passages`, `build_search_tool`
- `services/chatbot/agents/rag/prompts.py` — `RAG_INSTRUCTION`, tool name/description, passage templates
- `services/chatbot/agents/rag/types.py` — `RagState`, `KnowledgeBasePassage`, `SearchKnowledgeBaseArgs`
- `services/chatbot/agents/registry.py` — `run_agent_turn` (dispatches on `ChatbotAgentTypeEnum`; rag needs the OpenAI client)
- `services/chatbot/provider_errors.py` — `to_provider_error`, `CHAT_MODEL_ERRORS` (Anthropic error mapping shared by both agents)
- `services/chatbot/history.py` — agent-agnostic history plumbing: `summarize_if_needed`, `to_langchain_messages`, `extract_final_reply` (empty → `ChatbotProviderError`), `validate_turn_input`, kickoff message, `has_user_turn`, `insert_after_leading_system`
- `services/chatbot/types.py` — shared `ChatbotTurnResult`, `ChatbotSource`, `ChatbotMessageDict`
- `services/chatbot/session.py` — `process_chatbot_session_message` (Celery worker body: load session + history; an inactive session gets a failure webhook and no turn; for rag sessions builds the OpenAI client in the first DB block (missing credentials / bad knowledge bases → failure webhook); runs `run_agent_turn` with the stored `collected_fields`, stores the reply and updates `collected_fields` / `completion_status`, POSTs the webhook)
- `services/chatbot/config.py` — `resolve_chatbot_model_settings` (saved config + request overrides → `ChatbotModelSettings`, incl. `instructions`, `knowledge_base_ids`, `max_num_results`; 404 via `ConfigVersionCrud`, 422 for non-Anthropic/non-text/no-model configs), `prepare_rag_search_client` (non-empty `knowledge_base_ids`, each a non-deleted OpenAI collection's `knowledge_base_id` via `CollectionCrud.read_all`, plus OpenAI credentials → client)
- `services/chatbot/utils.py` — `ChatbotModelSettings`, defaults (`DEFAULT_MAX_OUTPUT_TOKENS`, `DEFAULT_HISTORY_TOKEN_LIMIT`, `FLOW_KEEP_RECENT_MESSAGES`), `get_chat_model`
- `services/chatbot/chatbot_ref.py` — `generate_chatbot_ref` (random `LLMResponseWithPrompt-<5 hex>`, retried against `chatbot_ref_exists` up to `CHATBOT_REF_MAX_ATTEMPTS`, else `ChatbotRefGenerationError`)
- `crud/chatbot.py` — `chatbot_ref_exists`, `create_chatbot_session` (also supersedes prior active sessions via `_deactivate_active_chatbot_sessions`; raises `ChatbotSessionConflictError` on the active-session unique index), `get_chatbot_session`, `get_latest_chatbot_session`, `update_chatbot_session_progress`, `create_chatbot_session_message`, `list_chatbot_session_messages`
- `crud/config/version.py` — `ConfigVersionCrud.read_latest` (used when `config_version` is omitted)

## Async
- `celery/tasks/job_execution.py` — `run_chatbot_session_message` (enqueued via `celery/utils.py:start_chatbot_session_message`) → `process_chatbot_session_message`.
- Webhook success payload: `{"success": true, "data": {"session_id", "chatbot_ref", "agent_type", "reply", "status", "completion_status", "collected_fields", "sources": [{"file_id", "filename"}]}}`; failure: `{"success": false, "error", "data": {"session_id"}}`.

## External
- Anthropic via `langchain-anthropic` (`ANTHROPIC_API_KEY` setting) — onboarding: two calls per turn once the user has spoken (extraction + reply); rag: one call per tool round (≤ 4); plus one summary call when history exceeds the token budget.
- OpenAI vector store search (`vector_stores.search`, rag only) with the project's OpenAI credentials, one call per knowledge base per tool call; `OPENAI_TIMEOUT_SECONDS`, one SDK retry.
- Caller webhook (`send_callback`, HMAC-signed with the project webhook secret).
